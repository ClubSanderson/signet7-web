One bounded contract

Accepted request ≠ persisted record.

The API accepts explicit request fields, but the ledger stores a bounded payload. The raw message body and submitted VSN signature/public key are not persisted verbatim.

Required intakeAgent ID, message ID, claimed sender, message body and requested action.
Optional intakeVSN signature and public key for supported provenance evaluation.
FingerprintCovers raw identifiers, body hash, action and optional provenance inputs; it is not a transcript.
Persisted payloadProtected identifiers, request fingerprint, action, provenance auth state and policy verdict.
Chain metadataTenant/record/time, sequence, nonce, previous hash, signer metadata and signature.

Record path

Five explicit steps.

CallerSubmits the explicit request through HTTP/OpenAPI, the MCP decision tool or an integrated caller.
ScopeNormalizes tenant and resolves credential role and provenance inputs.
PolicyEvaluates current exact-action rules and returns a verdict status.
LedgerCanonicalizes, chains and signs the bounded persisted payload.
VerifierChecks integrity plus supplied signer, tenant and expected-head inputs.
Enforcement boundary. The integrating caller must act on the returned policy result before external execution.

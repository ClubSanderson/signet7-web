Implemented surface

A real cryptographic core.
Precisely bounded.

Current draft claims follow source code and authored tests—not a roadmap, Terraform template, release tag, or sales sentence.

01

Signed evidence ledger

Ed25519 signatures, canonical serialization, nonces, previous-hash chaining, export, and standalone verification against an external trust root.

02

Tenant boundaries

Tenant normalization, tenant-specific ledgers and trust registries, scoped API keys, role checks, and authored cross-tenant isolation tests.

03

Storage and signing adapters

JSONL and SQLite persistence plus DynamoDB adapter code; local signing plus per-tenant AWS KMS adapter code; optional S3 Object Lock anchoring.

04

Policy decisions

A narrow rule engine returns explicit allow or blocked verdicts with provenance warnings where applicable. It is not a general policy-authoring platform.

05

VSN product profile 1.0

The v2 bound-payload method signs sender, message identifier, and body. Optional DNS discovery reads _vsn-auth.<domain> when a resolver is configured. Legacy body-only verification is disabled by default.

06

Interfaces

Flask/Waitress HTTP API, OpenAPI description, CLI, export/verifier utilities, metrics, and a limited stdio MCP tool.

Claim boundary

What the candidate proves—and what it does not.

Supported by source and authored tests

  • Signed, hash-chained, tamper-evident decision records.
  • Tenant-scoped API roles and authored isolation tests.
  • Multiple persistence and signing backends.
  • Optional external head anchoring and timestamp-response capture.
  • VSN sender/message/body binding with optional, separately configured DNS key lookup.
  • Automated tests are authored for core, isolation, packaging, and deployment contracts.

Not established

  • No verified production deployment, SLA, hosted service, or customer pilot.
  • No automatic universal seven-year retention or deletion lifecycle.
  • No general SPF, DKIM, DMARC, sender-behavior, or inbox gateway product.
  • No enterprise SSO/MFA or persistent credential-lifecycle service.
  • No independent audit, penetration test, SOC 2 report, or certification.
  • No claim that a legal entity, Partner status, or signing authority exists.
Language matters. “Tamper-evident” describes the default ledger. “Tamper-proof,” “immutable,” “compliant,” “certified,” and “production-ready” require evidence that this repository does not currently contain.
